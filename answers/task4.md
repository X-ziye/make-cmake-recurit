# Task 4：思考题

## 1. Make 和简单的 build.sh 有什么区别？

build.sh 是shell脚本，每次运行都会**完整执行所有gcc命令**，不管文件是否改动，没有依赖感知。
Make 会读取Makefile，对比文件时间戳，**只编译改动的文件及其依赖项（增量编译）**，自动管理文件依赖，支持并行编译；编译出错会停止后续任务。

## 2. CMake 是编译器吗？

执行 `cmake --build build` 时，最终是谁在编译 C 源文件？

CMake**不是编译器**，它是构建系统生成工具，用来生成Makefile。
`cmake --build build` 本质调用make，**最终由gcc完成C源码编译**。

## 3. 为什么不希望每次都重新编译所有 `.c` 文件？

项目源码多，全部重新编译耗时巨大。增量编译只重新编译改动的文件，复用没有改动的目标文件，提升开发调试效率。
